**Status:** bounded source-inspection sample; not full ontology validation

**Manifest observation:** schema 2, generated 2026-10-19; 454 entries, `local_cloned_count` 453 at inspection time

## Method and evidence limits

For each selected entry, the local repository HEAD matched the full commit pin recorded in the local ignored manifest and its worktree was clean. Inspection was limited to README/license metadata and a small number of source paths relevant to candidate operations. Evidence labels below follow accepted ADR-010: README statements are `source-reported`; visible code structure is `code-inspected`. No code ran, no clone/fetch/submodule operation occurred, and no source content was copied into this note. Manifest classification and local-directory presence alone are not technical evidence. No legal conclusion or device/runtime verification is made.

## Coverage, gaps, and disposition

This sample offers examples for WiFi packet monitoring/active frame paths, BLE/USB HID, stored RF transmit, PN532/MIFARE operations, and captive-portal/cookie-handler structures. It does **not** establish a standalone `parameter extraction` or `data exfiltration` category. The `m5porkchop` README separately mentions file transfer, but its implementation was not inspected; a general HTTP/file-transfer feature is not automatically data exfiltration. Tags, README claims, and this six-project sample do not validate every representative protocol, every operation, or the full proposed ontology. Network-monitoring synthesis beyond packet capture, ESP-NOW, MQTT, CSI, IR, and other categories need separate pinned evidence or remain gaps.

No inference of category presence should be made solely from manifest tags. No current denominator, completeness percentage, rights clearance, runtime/device behavior, or publication eligibility is established here. The sample is a bounded design input for the proposed ADR only; Issue #99's acceptance decision and any downstream #100–#107 work remain separate owner/project gates.
