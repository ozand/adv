## Method and evidence limits

For each selected entry, the local repository HEAD matched the full commit pin recorded in the local ignored manifest and its worktree was clean. Inspection was limited to README/license metadata and a small number of source paths relevant to candidate operations. Evidence labels below follow accepted ADR-010: README statements are `source-reported`; visible code structure is `code-inspected`. No code ran, no clone/fetch/submodule operation occurred, and no source content was copied into this note. Manifest classification and local-directory presence alone are not technical evidence. No legal conclusion or device/runtime verification is made. For this validation increment, the six source-path observations are taken from the already reviewed public sample record at [Issue #99 comment 6280921475](https://github.com/ozand/adv/issues/99#issuecomment-6280921475); this is a bounded record-level validation, not a fresh local reinspection.

## Coverage, gaps, and disposition

This sample offers examples for WiFi packet monitoring/active frame paths, BLE/USB HID, stored RF transmit, PN532/MIFARE operations, and captive-portal/cookie-handler structures. It does **not** establish a standalone `parameter extraction` or `data exfiltration` category. The `m5porkchop` README separately mentions file transfer, but its implementation was not inspected; a general HTTP/file-transfer feature is not automatically data exfiltration. Tags, README claims, and this six-project sample do not validate every representative protocol, every operation, or the full proposed ontology. Network-monitoring synthesis beyond packet capture, ESP-NOW, MQTT, CSI, IR, and other categories need separate pinned evidence or remain gaps.

No inference of category presence should be made solely from manifest tags. No current denominator, completeness percentage, rights clearance, runtime/device behavior, or publication eligibility is established here. The sample is a bounded design input for the proposed ADR only. The owner accepted the structure as a direction for continued Issue #99 validation at [comment 6282186430](https://github.com/ozand/adv/issues/99#issuecomment-6282186430); that does not establish all acceptance criteria. Any downstream #100–#107 work remains separately governed and gated.
