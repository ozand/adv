# DeviceOps: инфраструктура агентной работы с ESP32

**Дата:** 2026-10-12. **Программа:** [#66](https://github.com/ozand/adv/issues/66). **Поставка документации:** [#67](https://github.com/ozand/adv/issues/67).

DeviceOps — предлагаемый сервис, который даёт локальным агентам, вебчатам и операторам одинаковые управляемые операции с ESP32: обнаружение возможностей, диагностику, настройку, развёртывание и получение проверяемых результатов. Cardputer ADV — первый профиль устройства, а не ограничение архитектуры.

Центр системы — **контракт операций, полномочия и исполнитель заданий**. MCP и CLI предоставляют доступ агентам; Skills описывают методику; ESP Web Tools остаётся необязательным браузерным установщиком и источником полезных подходов.

## Статус и границы

Владелец в координационном чате 12 октября 2026 года согласился с направлением DeviceOps и поручил создать задачи и документы в `ozand/adv`. Эта запись отражена в epic. Она не является принятием всех подробностей ещё не рассмотренного API, выбором языка реализации или разрешением на операции с оборудованием.

| Предмет | Статус этой поставки |
|---|---|
| Сервис как центр, независимость от браузерного прошивальщика | Направление подтверждено владельцем |
| Требования, архитектура, security-модель и API | Предложение для review; [ADR-014](../adr/ADR-014-deviceops-service-centered-agent-infrastructure.md) имеет статус Proposed |
| Диагностические исходники и контракты ADV | Существуют отдельно; см. ADR-006/009 и их фактическое evidence |
| DeviceOps daemon, MCP, новые Skills и веб-мост | Не реализованы этим пакетом |
| Подключение вебчата, USB, прошивка и аппаратная квалификация | Не выполнялись этим пакетом |

## Первый полезный результат

Один профиль ADV, один локальный исполнитель и две поверхности — CLI и MCP. На имитаторе они дают одинаковый ограниченный отчёт, соблюдают policy и корректно обрабатывают потерю ответа. После отдельного допуска тот же сценарий выполняется на точной установленной прошивке: подключение, `status`, отчёт. `run`, SD, звук и flash не запускаются как побочный эффект.

Не требуется сначала создавать облако, каталог всех ESP32-плат, веб-портал или OTA. Удалённый доступ и последующие возможности добавляются к уже проверенному ядру.

## Место в репозитории

`adv` остаётся публичной базой знаний. Здесь находятся оригинальные проектные документы, ADR и координационные issues. Предлагаемые stack и граница исходников постоянного сервиса описаны в [D01 / #68](D01-DECISION.md); отдельный runtime-репозиторий не создан, и решение требует явного принятия владельцем.

Не публиковать в `adv` runtime DB, токены, реальные USB-идентификаторы, приватные адреса, сырые логи, дампы и бинарные прошивки. Существующие [AGENTS.md](../../AGENTS.md), [ADR-007](../adr/ADR-007-publish-reviewed-research-captures-exclude-local-source-originals.md) и правила reviewed PR продолжают действовать.

Для старта локальным агентам: прочитать [AGENT_GUIDE](AGENT_GUIDE.md), затем взять D01. Проекты схем D02 и threat model D03 можно готовить параллельно; gate принятия не следует путать с запретом на подготовительную работу.
